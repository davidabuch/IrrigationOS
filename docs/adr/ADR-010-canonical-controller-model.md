# ADR-010: Canonical Controller Model

## Status

Accepted for v0.4.1.

## Context

The v0.4.0 model exposed `rachio:<native-id>` as controller and irrigation-area identity. This coupled Home Assistant registry identity, landscape overrides, and future intelligence layers to one vendor.

## Decision

Canonical controller identifiers are generated by IrrigationOS and persisted in config-entry data. Provider controller and zone IDs are represented only by explicit `VendorBinding` values. Canonical irrigation-area identifiers are permanent controller-slot identifiers.

Every registry snapshot includes observation time, freshness horizon, source quality, and endpoint-specific partial failures. Current watering is confirmed only after the current-schedule endpoint succeeds; an endpoint failure produces `unknown`, never an inferred `idle`.

Runtime provider construction uses a provider factory. Provider-neutral config and coordinator code depend on controller contracts and generic provider errors rather than constructing Rachio clients directly.

## Migration

Config-entry version 1 entries are discovered once during migration. The migration allocates and persists controller identities, maps existing landscape overrides from Rachio zone IDs to canonical slots, and updates matching Home Assistant entity and device registry identifiers before upgrading the entry to version 2.

## Consequences

- Canonical identity survives controller, vendor-zone, and landscape renames.
- Safe partial observations remain usable and diagnosable.
- Additional providers can be composed without modifying provider-neutral runtime code.
- v0.4.1 remains strictly Observation-only and adds no command endpoints.
